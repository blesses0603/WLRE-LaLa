# 架構及版本規劃

共用核心使用 Rust，未來負責遊戲協定、登入狀態、戰鬥及資源管理。Windows 與 macOS 使用 Tauri 並維持一致介面；Android 使用 Kotlin 與 Jetpack Compose。平台透過明確的核心介面及儲存適配器整合，避免重複實作核心邏輯。這些平台應用及遊戲邏輯尚未實作。

資源管理先提供與來源格式無關的相對路徑、資源清單比較、儲存介面、錯誤碼與可序列化 JSON 事件。清單的識別值由未來經確認的來源轉接器提供，不能視為已驗證的雜湊。比較結果只包含新增及變更，不會刪除本機檔案。介面不保證檔案系統安全：實際適配器必須防止符號連結逃逸、處理平台名稱衝突，並以暫存及原子替換保護更新。

後續依調查結果實作更新偵測、增量下載、已確認格式的安全解析與提取、完整性驗證、快取、失敗恢復與回滾、各平台儲存適配及進度日誌。不得將未確認的機制當作事實。

共用核心首個目標版本為 0.1.0；桌面版及 Android 版尚未設定版本。三者獨立演進，但所有 PR 版本號必須全域唯一；建立 PR 前檢查所有現有 PR。版本號為 PR 識別，不代表已發布。

## 共用核心介面與日誌基線

目前工作區只有資源管理套件。資源管理與平台儲存以 `ResourceStorage` 邊界區分；介面讀取已驗證的相對路徑，回傳檔案內容、檔案不存在或錯誤碼。介面尚未提供寫入或原子替換，不能用來宣稱已實作跨平台快取。未來網路、協定、登入與戰鬥分別負責傳輸、已確認封包、狀態及規則，這些模組及對外呼叫介面尚未建立。平台整合、執行緒、生命週期與資料所有權需在實作 FFI／JNI 前訂定並測試。

目前資源事件可序列化為 JSON，欄位為 `event`、`completed`、`total`、`error`；事件名稱與錯誤碼使用固定的大寫底線代碼，無錯誤時 `error` 為 null。此型別只記錄計數和固定代碼，不能放入帳密、權杖、封包或檔案內容。實際日誌輸出、其他模組事件、共同事件封裝與跨平台傳輸尚未實作；新增時須保留敏感資料防護並以測試驗證。

`.gitignore` 僅阻擋已列出的常見本機路徑與憑證副檔名，不能辨識所有遊戲素材或秘密，也不會移除已追蹤檔案；提交前仍須檢查內容。
