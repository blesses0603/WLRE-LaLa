# LaLa 功能與官方資源需求矩陣（P1 設計輸入）

本文件以**功能需要什麼資料**為中心，而不是以官方資料夾中有多少檔案為中心。唯一允許發出新版遊戲資源請求的來源是 `https://wlreftpsrc.chinesegamer.net/WLN/TW/`。不將舊專案下載 URL 當作新版白名單，也不將舊版內建遊戲檔案複製進本 Repository。

## 一、契約：功能先於下載

```text
LaLa 功能事件（例如開地圖／查看配方）
  → 功能登錄與權限狀態（已啟用／未啟用／尚無證據）
  → 資料需求（只需伺服器資料／需本機設定／需官方靜態資產）
  → 已核對的官方 DataPackage／MainPackage Manifest
  → 精確 AssetPath 或 Address → BundleID → DependIDs
  → 估算必要檔案與流量 → 校驗已有快取 → 只下載缺少／變更者
  → 限制體積／驗證完整性 → 安全解析／提取
  → 功能資料就緒（**不代表**遊戲伺服器授權任何操作）
```

**必要防呆**：沒有功能綁定不得下載；精確資產不存在須回報缺口；無關 Bundle 不下載；不得以資產分類或檔名猜測操作範圍；有加密／未知格式不繞過；重用快取要重新校驗；版本改變時不得回報本輪成功。

## 二、可由舊桌面程式證實的「候選資料需求」

下表中的 `Assets/ResourcesBuild/Data/` 是**舊桌面版資源解析使用的精確前綴**。表格名稱是舊版經測試的功能線索，**不是已證明它們存在於目前官方最新版的完整 AssetList，更不是此刻已獲下載授權**。

| 功能 | 舊版具體來源證據 | 候選官方資料需求 | 新版正式綁定狀態 |
| --- | --- | --- | --- |
| NPC（定位／對話） | `WLRe_lala/wlre/services/world/feature_resource_index.py` 的 `FEATURE_TABLES['npc']` | `Eve.bytes`、`NpcData_C.bytes`、`TalkData_C.bytes` | 舊版唯讀定位已有線索；新版官方 Manifest 精確對應待核對 |
| 背包／物品名稱 | 同檔 `FEATURE_TABLES['bag']` | `ItemData_C.bytes` | 需核對官方版本、Bundle 相依與內容 Schema |
| 製作／配方 | 同檔 `FEATURE_TABLES['crafting']` | `SmithData_C.bytes`、`ItemData_C.bytes` | 不得憑下載成功開放製作或扣料 |
| 遠征 | 同檔 `FEATURE_TABLES['expedition']` | `AdventureData_C.bytes`、`AdventureLvData_C.bytes`、`NpcData_C.bytes`、`NpcCareerData_C.bytes`、`TextData_C.bytes` | 需確認目前資料基準與伺服器任務／獎勵結果 |
| 角色／能力、戰鬥 | `wlre/services/battle/`、`wlre/core/state_battle_events.py` | 首先是伺服器狀態；名稱／圖示／技能資料需求仍待來源查證 | 無官方資產證據前，不強制下載素材 |
| 小地圖／導航 | `wlre/features/minimap/`、`wlre/services/world/smallmaps.py`、`navigation.py` | 可能含場景資料；**原圖與路由網格的現行等價來源尚未證明** | 必須與場景與投影資料分開驗證，不得偷用舊 ZIP |
| NPC 商店 | `wlre/services/world/npc_shop.py`、`npc_shop_evidence.py` | 需 NPC／物品相關資料，但商店操作是否允許需伺服器交易證據 | 資料就緒也不能放行交易 |
| 傳送門／場景 | `wlre/services/world/portal_links_1275.py`、`doors_1275.py` | 舊版 1275 Runtime 候選含 `StageMapData_C`、`EveDoorLinks`、`ScenesData_C` | 先核對場景／格點／事件一致性，禁止直接採 1262 門 ID |
| 協力／一般副本 | `wlre/features/cooperative/`、`wlre/features/dungeon/` | 先依伺服器清單與事件；舊 `instance_catalog_1262.json` 的 1275 等價來源未查明 | 未完成官方等價資料查證，不自動下載猜測檔案 |
| 聊天／組隊／帳號／效率紀錄 | `wlre/services/social/`、`wlre/network/`、`wlre/core/efficiency.py` | 主要依賴伺服器資料及本機設定，**可能完全不需官方 Bundle** | 明確標記純通訊需求，避免登入時大量下載 |
| 夥伴／寵物、物品圖示 | `wlre/services/battle/companions.py`、`wlre/ui/companion_ui.py` | 夥伴狀態來自伺服器，靜態名稱／圖片依使用畫面再查證 | 不自動推論 NPC 模型等同寵物資源 |
| 煉金、戰後補給、修理、帳篷 | `wlre/services/items/`、`wlre/services/world/tent.py` | 部分依賴已確認物品／配方資料，操作須伺服器回覆 | 以業務規則判斷是否需要載入素材，不一律預先下載 |

**關鍵補充**：桌面 `wlre/services/world/bundle_runtime_1275.py` 的 `_REQUIRED_TABLES` 列有 `Eve`、`ItemData_C`、`TalkData_C`、`TextData_C`、`SmithData_C`、`ScenesData_C`、`AdventureData_C`、`AdventureLvData_C`、`NpcData_C`、`NpcCareerData_C`，但這是**舊版 1275 基準的整合 Runtime 所需十表**，不意味每次只打開地圖或聊天都要取得十表。必須由各功能宣告最小必要集合，並追蹤真正的共用消費者。

## 三、舊版官方 Manifest 與新版安全差異

- 舊桌面 `wlre/services/official_manifest_sync.py` 只使用 `DataPackage`／`MainPackage` 的 `.version`、`.bytes`、`.hash`，其中 `.hash` 為 CRC32 小端表示；該模組的 `ManifestSpec.url()` 不接受 `json`／`report`。
- 舊桌面 `wlre/services/official_incremental_sync.py` 的 `build_update_plan` **要求呼叫端明確傳入 AssetPath 或 Bundle 名稱**，展開相依後才決定命中快取／重用舊內容／新增下載；如果沒有 selector 就拒絕執行。
- 舊桌面 `wlre/services/world/feature_resource_index.py` 為**唯讀診斷**，`can_send_packets=False`、`assets_ready=False`；此索引的分類結果**不可直接解鎖遊戲功能**。
- 舊桌面 `wlre/services/world/resource_classification.py` 的 `classify_asset_path` 具有檔名／目錄的啟發式分類；只可協助候選盤點，**不可充當可下載清單或可信依賴來源**。
- 新版目前 `resource-manager` 已具官方版號觀察、清單／封包、`feature_resources.rs` 功能綁定、`official_cache.rs` 損毀驗證與 `offline_cache.rs` 選定封包收據。但**最新功能綁定尚無真正舊版功能呼叫端接線**，不能宣稱已與 UI 或遊戲協定整合。
- 新版若仍以官方 `.json` 索引作權威更新資料，必須先釐清與舊版 `.version`＋`.bytes`＋`.hash` 的版本身分、內容驗證及平台適用性。**正式流程應以已核對的官方版本與二進位資料為可信根據，不以猜測 JSON 欄位代替。**
- 對來源加密認證應有獨立的可信摘要或簽章；官方 MD5／CRC32 主要用於傳輸損毀檢查。只要未確認可信數位簽章，就不能宣稱抗惡意竄改。

## 四、功能登錄資料的最小欄位建議

| 欄位 | 規格 |
| --- | --- |
| `feature_id` | 稳定唯一、跨平台共用，新增和重新命名須處理相容 |
| `display_name` | 台灣繁體中文的 UI 名稱 |
| `state` | 停用／可用但不需素材／待核實素材／可下載已確認素材／已就緒 |
| `source_basis` | 舊版程式路徑＋版本／正式官方索引身分＋精確 AssetPath／驗收結果 |
| `required_assets` | 已核對資產的 `package`、`AssetPath`／`Address`；不可只有模糊分類 |
| `dependencies` | 官方清單 Bundle 相依；與功能級依賴分開 |
| `trigger` | 功能被實際使用／設定後才下載；排程只能刷新曾啟用的範圍 |
| `availability` | 資源可用與**是否允許發送遊戲命令**需分成兩個旗標 |
| `download_budget` | 限制檔數／總位元組／單檔體積／每輪下載與行動網路策略 |
| `test_evidence` | 單元、模擬 HTTP、官方小範圍抽樣、桌面／Android 實際整合分開記錄 |

## 五、驗收案例（應先使用模擬索引與模擬下載）

| 案例 | 預期 |
| --- | --- |
| 無任何功能啟用，啟動更新服務 | 只查官方版本，不下載任何 Bundle |
| 僅啟用地圖 | 只有已確認地圖資產及遞迴相依 Bundle 進入計畫 |
| 之後啟用戰鬥 | 增加戰鬥必需 Bundle；共用快取校驗通過就重用 |
| 純伺服器功能（例如登入） | 明確宣告無素材時不觸發官方封包請求 |
| 未核對之 NPC／其他功能 | 拒絕下載並保留待核實狀態，不能退回全包 |
| 已選封包損毀 | 只重新下載該封包，未選封包不受影響 |
| 版本檢查期間更換官方 Manifest | 拒絕回報本輪更新成功，保留先前已驗證內容 |
| 離線 | 只報告實際已使用且仍通過檢查的封包可用；不宣稱全包、最新或伺服器操作安全 |
| 新增功能已選封包超額、未知相依、加密、惡意路徑 | 下載前拒絕，且不釋出部分成功狀態 |

## 六、落地順序與範圍界線

1. 已依 [舊版功能盤點與新版責任](舊版功能盤點與新版責任.md) 建立二十一種穩定功能 ID；接著確立各功能狀態、真正的資料需求與安全閘門，**不用先做 UI 或登入**。
2. 先從現有舊版可靠來源的四組候選（NPC、背包、製作、遠征）及一組純通訊功能建立**模擬官方索引**測試。
3. 再用官方 `.version`、`.bytes`、`.hash` 實際核對相容清單，只讀取必要索引與小範圍封包，不下載整包。
4. 僅選擇確認有等價官方來源的資產，將結果接入功能 Registry 與 Rust 快取；依賴未確認者保留「資料不可用」而非自動補猜測檔。
5. P2/P3/P4/P5 的業務功能才產生實際需求事件，分別在桌面與 Android 驗證；**功能開關與下載成功不構成遊戲伺服器指令授權**。

> 狀態：**已核對舊版部分精確資料表與功能的關係**；新版當前官方最新版各功能 BundleID 與實際 UI 觸發尚未查證，P1 不得標示全面完成。
