# LaLa 新版開發路線圖

> 本文件為**開發計畫與驗收門檻**，不是完成清單。除非有實際提交、測試與證據，任何階段均不可標記完成。
>
> 唯一遊戲資源來源：https://wlreftpsrc.chinesegamer.net/WLN/TW/

## 一、開發策略

- 採取**先共用核心與自動化驗證，再處理平台整合，最後擴充完整遊戲功能**的順序。
- 每個 PR 必須聚焦單一可驗收的工作範圍、綁定唯一預計版本號。PR 標題格式 `[vX.Y.Z] 繁體中文具體修改重點`，版號以外不得出現英文。
- 桌面版、Android 與 Rust 共用核心分別管理程式版本，但本 Repository 的 PR **標題版本號全域不得重複**。建立 PR 前檢查現有及歷史 PR；同一開啟中的 PR 可補提交，不重複增加版號。
- 前一階段的先決條件未滿足前，不得宣稱下一階段已正式完成。獨立功能可以試作或並行研究，但必須標明驗證狀態。
- 預計開發順序是 P0 → P1 → P2 → P3 → P4 → P5 → P6；允許依實際協定調查結果調整 P1/P2 的實作細節，但調整須記錄原因與風險。

## 二、階段明細

### P0：專案規範、架構及共用核心骨架

**交付項目**

1. 建立並維護 `AGENTS.md`、本文件、`docs/架構.md` 及官方資源調查紀錄。
2. 初始化 Rust Workspace，建立模組邊界、錯誤碼及結構化日誌的基本規格。
3. 確定 Windows/macOS 使用同一套 Tauri UI、Android 使用 Kotlin + Jetpack Compose，核心透過明確介面供各平台呼叫。
4. 建立符合最小權限原則的 GitHub Actions：格式檢查、靜態檢查與 Rust 單元測試。
5. 加入 `.gitignore` 等安全基線，避免快取、下載的遊戲素材、憑證及建置結果進入版本庫。

**驗收門檻**

- `cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace` 在已宣告的測試環境實際執行成功。
- CI 有可查看的執行結果，沒有把未測的 macOS／Android／實際伺服器功能當成完成。
- PR 版本號與標題符合規範；未合併的 PR 不視為正式版。

**現況備註**：PR #1 擬提供 Rust 資源管理的初步型別及文件；仍須以 PR 實際檔案、CI 與驗收紀錄確認，不能直接宣稱 P0 全部完成。

### P1：官方遊戲資源自動更新、下載、解析與提取

**先決條件**：P0 核心與測試基線可用。

**交付項目**

1. 調查指定伺服器可重現的目錄、索引／清單、檔案與授權範圍；分析是否有官方版本與完整性資訊。
2. 為實際存在的資料建立來源轉接器；識別新增、變更、無法確認狀態，**不得以猜測推斷最新版本**。
3. 背景檢查更新與排程節流；依伺服器實際能力實作條件式請求或清單比較。
4. 依照 **LaLa 正在使用的功能**，以官方索引中已驗證的精確資產對應及相依關係選擇必要資源；僅下載缺少或變更的封包，**不得預設下載整包官方遊戲資源**；支援下載限制、逾時、取消、受控重試、暫存與進度通知。
5. 針對已確認格式實作檔案識別、解析、安全提取；驗證完整性並保留來源追溯。
6. 建立僅記錄各功能已使用之資源的本機索引、快取、原子寫入及中斷後重新查詢並更新至最新版本；不提供版本狀態切換或上一版本回復。
7. 抽象化 Windows、macOS、Android 的儲存目錄和權限，並設計行動流量及背景工作政策。

**驗收門檻**

- 使用可重複測試資料驗證首次按功能下載、無變更不重載、新增與變更、功能相依、無關資源不下載、損毀、解包失敗、下載中斷後恢復、最新版本重新查詢及離線快取。
- 確認不跨越官方來源白名單、不寫出沙盒路徑、不使用非官方素材、不提交遊戲資源至 GitHub。
- **只有經實際驗證的格式才能宣稱支援自動提取**；沒有官方更新資訊時需呈現「無法確認最新狀態」。
- 對官方站的實際下載驗收必須獨立記錄，不得用模擬資料結果代替。

### P2：TCP、協定與登入核心

**先決條件**：P0；P1 已具備必要的資源機制或已確認登入功能不依賴完整資源庫。

**交付項目**

1. Rust TCP 連線、超時、取消、重連節流與工作階段生命週期。
2. 經實際封包證據確認的協定編碼、解碼、封包邊界與錯誤處理。
3. 登入狀態機：未連線、連線中、驗證中、已登入、登出、斷線及失敗。
4. 敏感資訊保護、可觀測事件、統一錯誤碼及不洩漏認證資訊的日誌。
5. 可重複執行的模擬伺服器整合測試。

**驗收門檻**

- 正常登入流程與失敗、逾時、半包／黏包、意外斷線及重連測試有實際結果。
- 使用者授權後，才安排對官方正式伺服器的低負載實際連線驗收；未取得證據前不得宣稱正式服已可登入。
- 不得在專案與 CI 中存入正式帳密。

### P3：Windows／macOS 一致的桌面客戶端

**先決條件**：P2 有可測試的公開核心介面；資源管理介面可供 UI 呼叫。

**交付項目**

1. Tauri 單一桌面 UI，深藍色科技視覺規範及共用元件。
2. 統一標題列、側邊欄、導航、登入畫面、連線／資源更新狀態與錯誤呈現。
3. 安全的前後端命令介面，串接 Rust 共用核心。
4. Windows 與 macOS 的權限、路徑、視窗、通知與打包適配。
5. 桌面平台的啟動、登入、資源更新與回歸測試。

**驗收門檻**

- Windows 與 macOS **分別**完成編譯與啟動驗證，UI 與互動規範一致。
- 至少覆蓋登入成功、錯誤、斷線、資源更新進度、失敗恢復等可用流程。
- Windows CI 成功不能取代 macOS 實機或原生平台驗收。

### P4：Android 獨立客戶端

**先決條件**：P2 核心介面穩定；平台間使用相同的資料結構及錯誤碼。

**交付項目**

1. Kotlin + Jetpack Compose 建立觸控友善的深藍色介面。
2. 安全的 Rust FFI/JNI 呼叫層，定義執行緒、生命週期、所有權與錯誤傳遞。
3. Android 獨立登入、連線、資源儲存與更新流程。
4. 背景工作、權限、流量、電量、當機回復及基本安全測試。

**驗收門檻**

- Android 應用可獨立啟動及執行已開發功能，不需桌面程式。
- 實際完成建置、安裝、啟動和核心整合測試；模擬器與實機結果分開記錄。
- 與桌面版保持共同業務規則、事件格式及錯誤碼。

### P5：遊戲功能逐項完成

**先決條件**：P2 通訊與登入狀態可用，P3／P4 已有穩定整合界面。

**建議順序**

1. 帳號及角色／遊戲狀態管理。
2. 地圖與移動。
3. 戰鬥與戰鬥狀態。
4. 物品與背包。
5. 遠征。
6. 社交及其餘已確認功能。

**驗收門檻**

- 各功能列出實際協定證據、模組責任、正常／例外情境、單元及整合測試。
- 核心邏輯集中在 Rust，桌面與 Android 僅實作介面及平台能力。
- 每項功能須檢查回歸測試，未驗收者不可標示已完成或可用於正式服。

### P6：跨平台整合、穩定性與正式驗收

**先決條件**：預定發布範圍的功能已各自通過階段驗收。

**交付項目**

1. Windows、macOS、Android 的建置、啟動、安裝、登入、資源更新及功能回歸測試。
2. 非同步競態、資源與記憶體使用、重連節流、當機恢復及長時間穩定性測試。
3. 統一日誌與錯誤碼的跨平台一致性、安全與祕密掃描。
4. 官方伺服器相關功能的授權範圍、實測結果及環境記錄。
5. 正式發佈清單與已知限制；**未經使用者核准不得合併、打標籤或建立 Release**。

**驗收門檻**

- 每平台逐項列出「通過／失敗／未執行／不適用」與證據，不能用單平台結果推定其他平台。
- 跨平台版本與 PR 版本無衝突，沒有未處理的重大缺陷或未揭露風險。
- Release 僅在明確授權後才可執行。

## 三、每個 PR 的執行工作流程

1. 讀取最新 `main`、架構、路線圖、相依模組、當前版本以及所有尚未合併 PR。
2. 確認本 PR 對應階段、平台／核心版本線、**全 Repository 唯一目標版本**、範圍和驗收條件。
3. 建立獨立分支；若工作屬於同一尚未合併版本，優先續用該 PR，**不得為同版本另開 PR**。
4. 分析風險與回歸範圍；先建立或更新相應測試，再實作必要程式與文件。
5. 執行格式檢查、靜態檢查、單元／整合／回歸測試；必要時進行各平台啟動與正式伺服器驗收。
6. 重新確認 `main` 與其他 PR 的版本號，解決衝突後才建立／更新 PR。
7. PR 標題必須是 `[vX.Y.Z] 繁體中文具體修改重點`，標題中的英文字母僅允許 `v`。
8. 用繁體中文報告：PR 連結、版本線、原始／預計版本、實作內容、測試證據、未完成事項、風險與合併狀態。
9. 等待使用者明確授權合併；禁止自行推送 `main`、刪除分支或發布。

## 四、第一個里程碑與驗收紀錄方式

- 目前預定由 PR #1 `[v0.1.0] 初始化共用核心與資源管理基礎` 承載 P0 的起始工作；**此版本只是未合併的候選版本**。
- P0 之後先完成可驗證的官方資源偵測與資源處理（P1），再建立通訊與登入（P2），但若技術依賴允許，可並行設計不互相阻塞的模組。
- 對每個階段與每個 PR 持續保存：測試環境、指令或案例、結果、時間、失敗原因、證據連結及未測項目。文件與畫面截圖不是正式伺服器驗收的替代品。

本路線圖後續可依**實際調查與測試**更新，但不可追溯改寫未曾完成的成果。
